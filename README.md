# Курсовые работы — AWS Coursework

Веб-приложение для загрузки и просмотра курсовых работ в формате PDF.

Файлы хранятся в Amazon S3, а информация о студентах и загруженных работах — в Amazon RDS PostgreSQL. Приложение размещено на Amazon EC2.

## Доступ к сайту

Адрес:

https://courseworks.3-26-171-130.sslip.io

Сайт защищён логином и паролем. Учётные данные для проверки предоставляются отдельно.

Для использования сайта не требуется устанавливать проект, иметь аккаунт AWS или настраивать доступ к базе данных.

## Возможности

- Загрузка PDF-файлов размером до 20 МБ.
- Указание ФИО студента и учебной группы.
- Хранение файлов в Amazon S3.
- Сохранение метаданных в PostgreSQL.
- Просмотр списка загруженных работ.
- Открытие и скачивание файлов по временным подписанным ссылкам.
- Защита сайта и API логином и паролем через Nginx.
- Проверка подключения API к базе данных.

## Архитектура

```text
Браузер пользователя
        │
        │ HTTPS
        ▼
Nginx на Amazon EC2
        │
        ├── Статические файлы React
        │
        └── Запросы /api/*
                │
                ▼
          Express API
                │
                ├── Amazon S3
                │   PDF-файлы
                │
                └── Amazon RDS PostgreSQL
                    Метаданные загрузок
```

Nginx отдаёт собранный интерфейс и перенаправляет запросы `/api/` серверу Express.

Express слушает локальный адрес `127.0.0.1:3001`. Пользователи обращаются к приложению через Nginx, а не напрямую к порту API.

## Как работает загрузка

1. Пользователь входит на сайт.
2. Заполняет ФИО и группу.
3. Выбирает PDF-файл.
4. Сервер проверяет наличие полей, размер файла и расширение имени.
5. Файл загружается в S3 с уникальным ключом в префиксе `kursovie/`.
6. В PostgreSQL сохраняются метаданные.
7. Список работ обновляется.

Если после загрузки объекта в S3 возникает ошибка записи в базу, сервер проверяет наличие записи и при необходимости пытается удалить объект.

### Открытие файла

1. Пользователь нажимает «Открыть».
2. API получает из базы бакет и ключ объекта.
3. Создаёт подписанную ссылку S3 со сроком действия 5 минут.
4. Браузер переходит по этой ссылке.

Постоянный публичный доступ к объектам для такого механизма не требуется.

## API

Все указанные маршруты в опубликованной версии проходят через защиту Nginx.

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка соединения с PostgreSQL |
| GET | `/api/uploads` | Получение списка работ |
| POST | `/api/uploads` | Загрузка PDF и сохранение метаданных |
| GET | `/api/uploads/:id/download` | Получение временной ссылки на файл |

### Проверка состояния

Успешный ответ `/api/health`:

```json
{
  "status": "ok",
  "database": "connected"
}
```

Этот маршрут проверяет базу данных, но не подтверждает работоспособность загрузки в S3.

### Загрузка файла

Запрос `POST /api/uploads` использует `multipart/form-data`.

| Поле | Содержимое |
|---|---|
| `student_name` | ФИО студента |
| `student_group` | Учебная группа |
| `file` | PDF-файл до 20 МБ |

## Настройка окружения

### Требования

- Node.js 24 и npm.
- PostgreSQL с таблицей `coursework_uploads`.
- Бакет S3.
- Сетевой доступ приложения к PostgreSQL.
- Разрешения AWS для работы с файлами S3.
- Набор доверенных сертификатов Amazon RDS.

### Установка зависимостей

```bash
git clone [https://github.com/LoadOnnik/aws-coursework.git](https://github.com/LoadOnnik/aws-coursework.git)
cd aws-coursework

cd server
npm install

cd ../client
npm install
```

### Переменные окружения сервера

Создайте `server/.env` по образцу `server/.env.example`:

```dotenv
PORT=3001

AWS_REGION=ap-southeast-2
S3_BUCKET=your-bucket-name

DB_HOST=your-rds-endpoint
DB_PORT=5432
DB_NAME=your-database-name
DB_USER=your-database-user
DB_PASSWORD="your-database-password"

DB_SSL_CA=./global-bundle.pem
```

Не публикуйте действующие пароли в `.env.example`.

Для подключения к PostgreSQL приложение использует TLS с проверкой сертификата сервера.

Скачать набор сертификатов RDS можно из папки `server`:

```bash
curl -fSL \
  [https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem](https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem) \
  -o global-bundle.pem
```

### Доступ к S3

На EC2 приложение использует IAM-роль сервера. Постоянные AWS-ключи в исходном коде не требуются.

Роли нужны следующие действия над объектами в префиксе `kursovie/`:

```text
s3:PutObject
s3:GetObject
s3:DeleteObject
```

При запуске вне EC2 необходимо отдельно настроить учётные данные, поддерживаемые AWS SDK.

## Сборка и запуск

### Сборка интерфейса

```bash
cd client
npm run build
```

Готовые файлы появятся в `client/dist/`.

В развёрнутой конфигурации они копируются в:

```text
/var/www/courseworks/
```

### Ручной запуск API

```bash
cd server
node index.js
```

Адрес API:

```text
http://127.0.0.1:3001
```

Для работы интерфейса нужен веб-сервер, который отдаёт сборку React и перенаправляет `/api/` на Express. Один запуск API не публикует интерфейс.

### Служба systemd на EC2

В развёрнутой конфигурации API работает как служба:

```text
courseworks-api
```

Проверка состояния:

```bash
sudo systemctl status courseworks-api --no-pager
```

Перезапуск:

```bash
sudo systemctl restart courseworks-api
```

Просмотр журналов:

```bash
sudo journalctl -u courseworks-api -n 50 --no-pager
```

Не запускайте второй экземпляр `node index.js`, если служба уже использует порт 3001.

## Безопасность

- Сайт и API защищены HTTP Basic Authentication на уровне Nginx.
- Учётные данные следует вводить только через HTTPS.
- Доступ EC2 к S3 предоставляется через IAM-роль.
- Разрешения S3 ограничены префиксом с файлами приложения.
- Доступ к PostgreSQL разрешён для security group сервера приложения.
- Подключение к PostgreSQL использует TLS с проверкой сертификата.
- Скачивание файлов выполняется через временные подписанные ссылки.
- Пароли, приватные SSH-ключи и файл `.env` не должны попадать в Git.

Проверка PDF в текущей версии основана на расширении имени файла. Приложение не выполняет антивирусную проверку или полноценный анализ содержимого документа.

Basic Authentication предоставляет общий доступ к приложению и не реализует отдельные роли студентов и преподавателей.

## Проверка проекта

1. Открыть сайт по HTTPS.
2. Ввести предоставленный логин и пароль.
3. Указать тестовые ФИО и группу.
4. Загрузить небольшой PDF без конфиденциальных данных.
5. Убедиться, что работа появилась в таблице.
6. Нажать «Открыть» и проверить доступ к файлу.
7. При необходимости проверить объект в S3 и запись в RDS через AWS Console.

## Ограничения демонстрационной версии

- Поддерживаются только PDF-файлы до 20 МБ.
- Нет регистрации пользователей и разграничения доступа к отдельным работам.
- Нет удаления работ через интерфейс.
- Приложение размещено на одном EC2-сервере.
- Бесплатное имя sslip.io привязано к публичному IP сервера. При изменении IP потребуется обновить адрес и настройки HTTPS.
- Использование EC2, RDS и S3 может приводить к расходам AWS.
